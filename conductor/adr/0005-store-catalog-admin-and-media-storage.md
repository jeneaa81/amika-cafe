# ADR-0005: Архитектура админки витрины магазина (Store Catalog Admin), гибридного медиа-хранилища и сквозного стоп-листа

## Статус
Предложено к утверждению (Proposed for Approval)

## Контекст и проблематика
В предыдущей версии системы кабинет администратора (`AdminBuilder.tsx`) управлял только текстовыми позициями двух колонок цифрового меню для телевизора (Кофе и Чай/Десерты) и слайдами ТВ. 

Витрина гостевого каталога в Telegram Mini App (`@AmikaCafeBot`) оперирует значительно более богатым набором данных:
1. Качественные фотографии блюд и напитков.
2. Двуязычные названия и описания (RO / RU).
3. Категории (`coffee`, `matcha_tea`, `foodberry`, `breakfast`, `merch`).
4. Модификаторы кастомизации (молоко обычное/растительное, сиропы, температура горячий/айс, одинарный/двойной шот).
5. Промо-бейджи («Хит продаж», «Выбор бариста», «Foodberry Fresh»).
6. Мгновенный статус наличия (стоп-лист).

Владельцу кофейни требуется возможность быстро обновлять фотографии, тексты и ассортимент витрины со своего смартфона или ноутбука без участия программиста.

### Факторы принятия решений (Decision Drivers):
1. **Эргономика и простота для владельца:** Все рычаги управления кофейней (ТВ, витрина Mini App, карты лояльности) должны быть доступны в один клик под единым паролем.
2. **Единый источник данных без дублирования:** Изменение цены или названия в каталоге магазина должно автоматически отражаться на ТВ-борде при установленном флаге синхронизации.
3. **Удобная загрузка фото с мобильного устройства:** Владелец должен иметь возможность сфотографировать свежий десерт на телефон и сразу выставить его на витрину.
4. **Оперативный стоп-лист для бариста:** Бариста за стойкой не должен тратить время на ввод паролей администратора, если молоко или десерт закончились прямо сейчас.

## Рассмотренные альтернативы и решения

### Решение 1: Размещение интерфейса админки
- **Выбранное решение: Единый кабинет администратора (`?mode=admin`).**
- **Обоснование:** Добавление вкладки «Витрина / Товары» внутрь существующего защищенного кабинета `AdminBuilder`. Это исключает фрагментацию интерфейсов, дублирование аутентификации и сессий, обеспечивая управление всей экосистемой из одного окна.

### Решение 2: Взаимосвязь витрины магазина и Smart TV в зале
- **Выбранное решение: Единый мастер-каталог с селективным отображением на ТВ.**
- **Обоснование:** Товар создается и редактируется в каталоге витрины. В карточке предусмотрен чекбокс `showOnTv: boolean` и выбор колонки (`Col 1: Cafea` или `Col 2: Bauturi & Deserturi`). При изменении цены в магазине цена на экране ТВ обновляется автоматически по SSE без двойного ввода.

### Решение 3: Хранение и загрузка фотографий
- **Выбранное решение: Гибридный медиа-менеджер.**
- **Архитектура загрузки:**
  1. *Клиентская оптимизация:* Загружаемые с камеры/галереи фото автоматически сжимаются на клиенте через HTML5 Canvas (`compressImageFile`: WebP/JPEG, max 800px, качество 0.82, вес < 80 КБ).
  2. *Облачное хранение:* Сжатые изображения загружаются в Supabase Storage (публичный bucket `store-images`) с автоматической генерацией публичного CDN URL. При сбоях соединения или локальном оффлайн-режиме поддерживается сохранение inline Base64 в объекте конфигурации.
  3. *Встроенная галерея пресетов:* Готовая библиотека качественных студийных фото Specialty-кофе, чая матча и крафтовых круассанов Foodberry для моментального выбора без съемки.
  4. *Прямая ссылка (URL):* Поле ручного ввода внешнего URL для быстрой вставки ссылок из соцсетей или Unsplash.

### Решение 4: Доступ к стоп-листу для бариста
- **Выбранное решение: Быстрый переключатель на экране бариста (`?mode=barista`).**
- **Обоснование:** На экране бариста добавляется компактная выдвижная панель «Стоп-лист витрины». Бариста в 1 касание переключает статус позиции (`В наличии` / `Закончился`). Изменение моментально блокирует заказ позиции в клиентском Mini App через Supabase Realtime без ввода админ-пароля.

## Схема структуры данных каталога (`store_products`)

В таблице `public.menu_config` (или сопутствующей структуре `store_products`) каждый товар расширяется до полной модели:

```typescript
export interface StoreProduct {
  id: string;
  name: { ro: string; ru: string };
  description: { ro: string; ru: string };
  price: number;
  secondPrice?: number;
  volume?: string;
  secondVolume?: string;
  category: 'coffee' | 'matcha_tea' | 'foodberry' | 'breakfast' | 'merch';
  image: string; // URL из Supabase Storage, пресет или внешний URL
  badge?: { ro: string; ru: string };
  visible: boolean; // Статус стоп-листа (в наличии / скрыт)
  showOnTv: boolean; // Транслировать ли на Smart TV
  tvColumn?: 'coffee' | 'desserts'; // В какую колонку ТВ направлять
  options: {
    milk?: boolean;
    syrup?: boolean;
    temperature?: boolean;
    dose?: boolean;
  };
  sortOrder: number;
  updatedAt: string;
}
```

## Последствия принятия решения

### Положительные (Pros):
- **100% автономия владельца:** Смена фото, описаний, цен и запуск сезонных новинок выполняются в 3 клика прямо с мобильного телефона.
- **Никаких расхождений:** Синхронизация между витриной, экраном предзаказов бариста и ТВ-бордом работает автоматически из единого источника.
- **Оптимизация трафика:** Загружаемые владельцем тяжелые фото с камеры (5-10 МБ) сжимаются до легковесных <80 КБ, не перегружая мобильный интернет гостей кофейни.
- **Мгновенная реакция за стойкой:** Закончившийся десерт Foodberry скрывается бариста за 1 секунду.

### Компромиссы и риски (Trade-offs & Mitigations):
- **Лимиты Supabase Storage:** При бесплатном тарифе Supabase лимит хранилища составляет 1 ГБ. Благодаря обязательному сжатию картинок до ~80 КБ этого объема хватит более чем на 12 000 фотографий, что с запасом покрывает потребности кофейни на годы вперед.

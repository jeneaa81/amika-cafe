# ADR-0001: Защищенная серверная отправка Telegram Push-уведомлений через Supabase Database Webhook / pg_net

## Статус
Принято (Accepted)

## Контекст и проблематика
В рамках экосистемы Amika Café гость оформляет предзаказ в Telegram Mini App, а бариста на экране планшета меняет статус на `ready` («Готов к выдаче»). В этот момент гость должен получить персональное push-сообщение в Telegram:  
*«☕ Михай, ваш заказ #102 готов! Ждем вас у стойки Amika Café»*.

Фронтенд проекта развернут на **GitHub Pages** в виде статических файлов. Вызов Telegram Bot API требует секретного токена бота (`8935606630:AAHf5kRs...`). 

### Факторы принятия решений (Decision Drivers):
1. **Безопасность токена:** Секретный токен бота ни при каких условиях не должен попасть в публичный JavaScript-бандл или сетевой трафик клиентского браузера.
2. **Нулевая стоимость инфраструктуры:** Решение должно укладываться в бесплатные лимиты Supabase и GitHub Pages без необходимости разворачивать платный VPS-сервер.
3. **Надежность доставки:** Отправка уведомления должна происходить гарантированно, даже если у бариста моргнул Wi-Fi или закрылась вкладка браузера сразу после нажатия кнопки.

## Рассмотренные варианты

### Вариант 1: Прямой HTTP fetch из браузера бариста (Client-Side)
- **Плюсы:** Быстрая реализация без серверных настроек.
- **Минусы:** Секретный токен бота зашивается в клиентский бандл. Любой пользователь может извлечь его и захватить контроль над ботом `@AmikaCafeBot`. Ненадежно: разрыв связи на планшете бариста приводит к потере уведомления.

### Вариант 2: Серверный триггер в базе данных через Supabase Database Webhooks / расширение `pg_net`
- **Плюсы:** 
  - 100% изоляция токена: токен хранится в переменных окружения Supabase (Vault / App Settings) и недоступен клиентам.
  - Транзакционность: отправка происходит на уровне базы данных при событии `UPDATE orders SET status = 'ready'`.
  - Отсутствие отдельного бэкенд-сервера: вся логика исполняется в облаке Supabase.
- **Минусы:** Требуется разовая SQL-настройка триггера и активация расширения `pg_net` в панели Supabase.

### Вариант 3: Выделенный сервер (VPS на Node.js / FastAPI / Docker)
- **Плюсы:** Гибкость и классический бэкенд.
- **Минусы:** Требует ежемесячной оплаты хостинга, настройки доменов, SSL-сертификатов, мониторинга и обслуживания локальной кофейней. Избыточно для задачи.

## Решение
**Выбран Вариант 2 (Supabase Database Webhook / pg_net).**

1. Токен Telegram-бота сохраняется в Vault / конфигурации Supabase.
2. В таблице `public.orders` создается триггер: при изменении `status` на `'ready'` триггер вызывает хранимую процедуру, которая формирует HTTP POST запрос к `https://api.telegram.org/bot<TOKEN>/sendMessage` через расширение `pg_net`.
3. Бариста на планшете выполняет стандартный защищенный `UPDATE` статуса заказа, не зная токена бота.

## Последствия

### Положительные:
- Полная безопасность учетных данных Telegram-бота.
- Гарантированная отправка уведомления независимо от состояния планшета бариста.
- Архитектура остается serverless (статический фронтенд + Supabase).

### Отрицательные / Риски:
- Зависимость от доступности внешнего Telegram Bot API со стороны инфраструктуры Supabase.
- Необходимость однократного применения миграции SQL-скрипта в Supabase SQL Editor.
